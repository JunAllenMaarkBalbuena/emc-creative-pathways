## 3. The 30 flagged `%` refs are not breaks

`audit_nodepaths.py` checks each script's `%Name` against the *scene's own*
`SceneState`. The 30 flags are all test-harness scenes that instance
`modeling_lab.tscn` / the digital-art lab and reach inside with `%Name` (e.g.
`test_skew_toggle.gd` → `%SkewToggle`, `test_workspace_origin.gd` →
`%WPosY/%PosY/%TransformLabel`). The instanced scene's inner nodes are not in the
test scene's `SceneState`, so the static tool cannot see them; the target scenes
*do* declare `unique_name_in_owner` (modeling_lab.tscn alone has 40+), and the same
lookups pass green at runtime in the gate. The one product-side flag
(`main.gd:854 %SaveCategoryOption` vs `digital_art_lab/test_verify.tscn`) is
over-reporting too: the node is declared (`digital_art_lab.tscn:412-413`) and
`test_verify.tscn` attaches a different harness script. Recommend a future
parser option to resolve `%` refs through instanced children; no code change needed.

## 7. Tooling findings (this machine / repo)

- **No Python interpreter installed** (`py`/`python` are Store stubs). The three
  10-05 audit tools (`audit_refs.py`, `audit_nodepaths.py`,
  `fix_ext_resource_paths.py`) were run under `uv`-managed CPython.
- **`audit_refs.py` cannot finish on this repo**: 5,734 tracked files including a
  50 MB `.ogv` make its whole-corpus `blob` ~100 MB and its per-file substring
  scans take 15+ minutes. Performance bug in the tool (whole-corpus `referenced()`
  design); the questions it answers were instead answered directly — engine loads
  (`audit_dump`: 0 failures ⇒ paths + uids resolve), `fix_ext_resource_paths
  --check` (0 stale), sidecar cross-check (0 orphans).
- **Engine churn on headless runs:** one run moved `project.godot`'s `[emc]`
  section and dropped its comment; reverted (`git restore project.godot`). The
  churn is occasional (two later boot batches did not re-trigger it) and
  content-identical; tree was clean at audit end. Same known class as the 10-05
  note on `data/skins/*.tres` + unique_id rewrites.
